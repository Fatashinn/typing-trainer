# Данные платформы 2.0 и резервные копии

## Исходные данные 1.x

Семь ключей 1.x сохраняются: `tt.settings`, `tt.stats`, `tt.history`,
`tt.custom`, `tt.totals`, `tt.days`, `tt.daily`. Имена и значения не
переносятся в новое хранилище и не удаляются при запуске. Исходные поля
статистики RU/EN не превращаются автоматически в подтверждённое мастерство,
XP или достижения. Исторические данные остаются вспомогательной информацией.

## Новый ключ `tt.platform`

```json
{
  "version": 1,
  "preferences": {
    "uiLanguage": "ru",
    "languageId": "fr",
    "layoutId": "fr-mac",
    "geometry": "ANSI"
  },
  "learning": {
    "version": 1,
    "xp": 0,
    "processed": {},
    "perDay": {},
    "skills": { "physical": {}, "character": {}, "bigram": {}, "text": {} },
    "nodes": {},
    "achievements": {}
  }
}
```

Точная схема `learning` описана в [MASTERY.md](MASTERY.md); пример показывает
разделение настроек и учебных данных, а не заменяет валидатор. `TT2.storage`
предоставляет `create()` и `validate(value)`: проверяет версию, четыре
независимые настройки и передаёт проверку учебного состояния движку мастерства.
Идентификаторы языков/раскладок имеют ограниченную длину и синтаксис; отсутствие
будущего пакета в текущем реестре не является основанием удалить его данные.
Интерфейс может предложить выбрать установленный пакет, сохранив исходные поля.

При отсутствии ключа создаётся пустое состояние без исторических наград.
При повреждённом ключе применяется прежняя защита хранилища: сырой исходник
не удаляется и не перезаписывается автоматически. Экспорт включает защищённый
исходник; импорт такого повреждённого содержимого отклоняется до исправления.

## Резервные копии

Новый экспорт использует `format: "typing-trainer-backup"`, `version: 2` и
ровно восемь ключей `entries`. Значения по-прежнему строки с исходным JSON
либо `null` для отсутствующей записи. Из памяти берётся актуальное состояние
`TT2.appState`, если оно загружено: отказ записи localStorage не должен
исключить новые результаты из скачиваемой копии. Проверка каждого значения
выполняется до импорта, а неподдерживаемая версия отклоняется явно.

Копии **v1 с ровно семью ключами** принимаются. Подтверждённый импорт v1
заменяет только семь разделов 1.x; уже существующий `tt.platform` сохраняется
без изменений. Таким образом, восстановление старой копии не удаляет новое
мастерство и XP. Предварительный просмотр явно сообщает это отличие.
Если нужен полный перенос платформы 2.0, следует использовать копию v2.
Импорт v1 в чистый профиль оставляет учебное состояние пустым.

Импорт v2 — полная подтверждённая замена восьми разделов, включая мастерство,
XP и настройки языков. `null` для `tt.platform` означает удаление платформенного
ключа при замене; следующий запуск создаёт пустое состояние. До подтверждения
доступно скачивание текущей копии. Слияние двух независимых учебных историй
не выполняется: оно могло бы продублировать награды и исказить мастерство.

Лимит файла из [BACKUPS.md](BACKUPS.md) сохраняется (8 МиБ); для записи
`tt.platform` допустимо до 6 млн UTF-16 единиц, для `tt.history` также 6 млн (контекстные события новых уроков), для остальных — прежние
2 млн. Само состояние мастерства ограничено 3 МиБ UTF-8: новое наблюдение
проверяется на копии и при превышении лимита отклоняется без изменения
исходного состояния. Лимиты модели также ограничивают число записей, а не молча удаляют
идентификаторы уже обработанных уроков. Импорт/перезагрузка не начисляют XP
заново: обработка результатов идемпотентна по устойчивому идентификатору урока.

## Восстановление при частичной ошибке

Перед заменой сохраняется и проверяется `tt.import-recovery.v1` с точными
предыдущими строками. Версия журнала осталась 1: его содержимое `before`
может включать старые семь или новые восемь ключей. Восстановление старого
журнала касается только присутствующих семи ключей и не удаляет `tt.platform`.
Новый журнал восстанавливает все восемь. При неудачном откате запись
приостанавливается; журнал остаётся до успешного восстановления.

Разные вкладки не образуют транзакцию localStorage. Перед импортом закройте
остальные вкладки приложения. Переносимый файл сохраняйте до обновления
сайта; проверку импорта и сбоев проводите в отдельном тестовом профиле.
Никакие резервные копии, собственные тексты или учебные данные не передаются
во внешние сервисы автоматически.
