# Платформа 2.0: архитектура первого рабочего среза

База — main `26861845` после PR #1/#2. Сайт остаётся статическим: `index.html`
и обычные локальные JS-файлы, без сборки, backend и runtime-пакетов.
Скрипты загружаются последовательно и работают также без ES module loader.
Для разработки рекомендуется локальный HTTP-сервер; GitHub Pages обслуживает
те же файлы. Упражнения и данные не отправляются в сеть.

## Четыре независимых измерения

- UI locale: ru/en, словари `platform/i18n.js`.
- Typing language: языковые пакеты ru/en/fr/de, `platform/languages.js`.
- Input layout: реестр `platform/layouts.js`, устойчивые id и определения v1.
- Geometry: ANSI/ISO; ISO — справочное расположение дополнительной клавиши,
  а не обещание проверенной аппаратной геометрии Return или кодов macOS.

Изменение одного поля не переключает остальные и не управляет системным
источником ввода. Несовместимые язык/раскладка явно показывают недоступные
символы. В диагностике они перечисляются как непокрытые; результат относится
только к проверяемой части. В учебном узле необходимые символы не удаляются
молча ради запуска. Выбранные настройки применяются к следующему упражнению;
у запущенного урока контекст закреплён и показан в его заголовке.

## Компоненты

- `languages.js`: содержательные данные и `registerLanguage`.
- `layouts.js`: карты слоёв, последовательности dead keys, поиск маршрутов
  символа и вспомогательное сравнение физического события.
- `learning.js`: чистая модель наблюдений, рекомендаций, 42 учебных узлов,
  мастерства, XP и достижений. Нет DOM, localStorage или сетевых запросов.
- `storage.js`: оболочка данных платформы и проверка схемы.
- `i18n.js`: словари ru/en, семантические ключи новых компонентов и адаптер
  перевода оставшихся компонентов 1.x без замены их обработчиков.
- `app.js`: UI, нативный текстовый ввод, связь с измерением времени и сохранением.
- `index.html`: сохранённые упражнения 1.x, физическая клавиатура, проверенное
  время и восстановление резервных копий. Старые MAPS/REV/OTHER изолированы
  в пути совместимости; новый контент их не расширяет и не использует для ввода.

Полного переписывания старого приложения нет. Новый реестр — основной путь
для уроков платформы, диагностики и свободной практики; старые режимы остаются
доступны без переноса статистики в новые метрики.

## Ввод и составные символы

Новый путь использует видимое поле ввода. `keydown` сохраняет физическую
клавишу/модификаторы, но конечный текст берётся из `input`. `beforeinput`
отклоняет вставку/замену, не являющуюся измеряемым печатанием. `compositionstart`,
`isComposing` и `compositionend` не дают принять префикс IME/dead key за ошибку.
Финальный текст нормализуется в NFC; конечное echo-событие подавляется.
Промежуточные dead keys не создают самостоятельных ошибок.

Для прямого ввода проверяются фактический `key`, физический `code` и выбранная
карта. Для составного ввода конечный символ можно проверить, но без надёжной
последовательности физических событий физическое освоение не подтверждается.
Option и AltGr описаны разными слоями; Ctrl+Alt трактуется как AltGr только
для PC-карт. Ctrl+Space/Cmd-комбинации остаются системными.

Автоопределение системной раскладки не является источником истины. Нет
зависимости от Keyboard Layout Map API, отсутствующего в Firefox. Неверный
прямой маршрут получает сообщение о проверке системной раскладки; совпадение
символа само по себе не доказывает текущий источник ввода ОС.

Начальные языки используют NFC-символы BMP. Полноценная сегментация любых
будущих графемных кластеров (например, индийских письменностей) не заявлена.
Пакеты таких языков потребуют расширения сегментации и отдельного набора тестов.

## Смешанная практика

Узел техники переключения использует первичный и вторичный выбранные
язык/раскладку. Участки текста имеют явный контекст; ожидаемая клавиатура
меняется с позицией, но системную раскладку меняет пользователь. Результат
делится по контекстам, включая подтверждённое активное время; обработанные
идентификаторы сохраняются отдельно, поэтому смешанная практика не смешивает
мастерство символов разных раскладок и не выдаёт награды повторно.

## Сохранение и границы

Семь ключей 1.x сохранены; `tt.platform` — отдельная схема v1. Наблюдения 2.0
не пишутся в старую EN/RU посимвольную статистику. Новые уроки используют
сохранённые таймеры и включают контекст/события в контрольную точку, позволяя
восстановить прерванный урок. Награды применяются к завершённым осмысленным
урокам по устойчивым id. Подробности: MIGRATIONS.md и MASTERY.md.

Внешний ИИ не подключён. JSON резервной копии не является аналитическим
протоколом. Исходный копируемый отчёт сохранён и локализуется независимо.
