# Резервные копии Typing Trainer

В настройках доступны скачивание JSON и импорт. Это переносимая резервная
копия, а не аналитический отчёт для ИИ. Никаких данных в сеть приложение
не отправляет; файл содержит также собственный текст пользователя.

## Формат v1

```json
{
  "format": "typing-trainer-backup",
  "version": 1,
  "exportedAt": "2026-11-13T10:00:00.000Z",
  "entries": {
    "tt.settings": "{\"mode\":\"symRU\",\"strict\":true}",
    "tt.stats": "{}",
    "tt.history": "[]",
    "tt.custom": null,
    "tt.totals": "{\"lessons\":0,\"ms\":0}",
    "tt.days": "{}",
    "tt.daily": null
  }
}
```

Все семь ключей обязательны. Значение — строка с исходным JSON либо `null`
для отсутствующей записи. Строки сохраняют поддерживаемые дополнительные
поля и позволяют выгрузить повреждённую запись без потери исходника.
Повреждённую запись нельзя импортировать до исправления структуры.
Настройки и текущая статистика выгружаются также из памяти: прогресс,
ещё не записанный на диск или не сохранённый из-за квоты, попадает в копию.
Скачивание не требует сначала записать прогресс в localStorage.

Импорт принимает только этот явно обозначенный формат версии 1. Старые
структуры внутри записей поддерживаются: частичные настройки, статистика
без `x`/`sx`, история без `ms`, `cnt`, `fast` и `shiftWarn`. Произвольный JSON,
аналитический отчёт или неизвестная версия отклоняются без изменения данных.
При запуске старые отсутствующие поля дополняются штатными значениями;
исходные повреждённые записи защищены от автоматических записей и сброса.

Ограничения: файл до 8 МиБ UTF-8, запись до 2 млн UTF-16 единиц,
собственный текст до 1 млн единиц, история до 10 000 уроков, до 2000
записей посимвольной статистики, до 100 путаниц в одной категории,
глубина JSON менее 16. Числа конечные, неотрицательные, не больше
`Number.MAX_SAFE_INTEGER`; точность не выше 100%. Проверяются типы,
обязательные поля, известные режимы и значения настроек. Ключи
`__proto__`, `prototype`, `constructor` запрещены во вложенных структурах.
Обычная история приложения по-прежнему ограничена последними 50 уроками.
Лимиты резервной копии не увеличивают квоту браузерного хранилища.

## Замена и восстановление

1. Закройте другие вкладки тренажёра. Импорт предназначен для одной вкладки:
   localStorage не предоставляет транзакцию или блокировку между вкладками.
2. Выберите JSON. Проверки выполняются до изменения пользовательских ключей.
3. Просмотрите дату и число уроков, скачайте текущую копию и убедитесь,
   что браузер действительно сохранил файл.
4. Отметьте подтверждение и нажмите «Заменить данные». Это полная замена,
   не слияние. Значение `null` удаляет соответствующую запись при замене.
5. После успеха страница перезагрузится и прочитает новые данные.

Перед заменой приложение записывает отдельный ключ `tt.import-recovery.v1`
с точными прежними строками всех семи записей. Запись журнала проверяется;
если для него не хватает места, импорт не начинается. После каждой записи
проверяется прочитанное значение. Журнал удаляется только после успешной
замены либо полного отката. Старое состояние в памяти не записывается
при перезагрузке страницы после импорта.

При ошибке выполняется откат прежних значений, включая отсутствие ключей.
Если откат тоже не удался, журнал остаётся, обычные записи блокируются.
Следующий запуск повторяет восстановление **прежнего** состояния, а не
продолжает импорт. Это же правило действует при закрытии браузера посреди
замены. Успешное восстановление сопровождается сообщением в настройках.

Если восстановление не удалось: сохраните уже скачанную резервную копию,
устраните причину отказа (например, освободите место на устройстве), затем
нажмите «Повторить восстановление». Не очищайте данные сайта и журнал:
они нужны для отката. Если повреждён сам журнал, автоматическая запись
остаётся заблокированной; требуется отдельное восстановление из сохранённой
копии. Не следует удалять повреждённые исходники без сохранения.

Изменение хранилища другой вкладкой отменяет подготовленный импорт и
приостанавливает запись до перезагрузки. Проверка исходного снимка перед
заменой дополнительно отклоняет устаревший предварительный просмотр.
Это защита от обычных конфликтов, а не гарантия транзакций между вкладками.

## Безопасная ручная проверка на MacBook

1. Текущая версия ещё не опубликована. Не начинайте проверку с очистки данных
   рабочего GitHub Pages: используйте локальную копию новой ветки и отдельный
   тестовый профиль браузера. Данные Pages и localhost принадлежат разным origins.
2. Откройте приложение, закончите короткое упражнение, измените настройки,
   сохраните свой текст. В настройках нажмите «Скачать JSON».
3. Откройте копию в другом тестовом браузере или профиле. Выберите файл:
   до подтверждения ничего не должно заменяться. Нажмите «Отмена» и проверьте
   сохранность прежних данных.
4. Выберите файл снова, скачайте текущую копию, подтвердите замену.
   После перезагрузки сравните настройки, историю, статистику и собственный текст.
5. В копии файла измените `version` на 999 либо `tt.history` на строку `"{}"`.
   Импорт должен отклониться; существующая статистика должна остаться.
6. Пройдите ещё один урок и перезагрузите страницу: запись должна работать.
7. Не воспроизводите нехватку места или повреждение localStorage в рабочем
   профиле: эти отказы проверяются автоматическими тестами в изолированных контекстах.

## Автоматические проверки

`node tests/trainer.test.js` — существующая регрессия.
`node tests/backup.test.js` — перенос, подтверждение, отмена, структура,
сохранность старых данных и искусственные сбои записи/отката.
Оба требуют Playwright с Chromium. Можно установить `TT_TEST_URL` для
резервных тестов, чтобы использовать локальный статический HTTP-сервер
вместо файловой навигации. Сборка приложения не нужна.

## Временные поля после стабилизации

Конверт v1 сохранён. Новые необязательные поля урока `timingVersion: 2`,
`id`, `status`, `activeMs`, `wpmMs`, `longBreaks`, `noSpeedSample` и раздел
`tt.totals.timingV2` проверяются при загрузке/импорте. Старые записи без них
принимаются. При восстановлении копии с незавершённой контрольной точкой
создаётся одна прерванная запись, без повторного начисления активности.
Подробности: [TIMING.md](TIMING.md).
