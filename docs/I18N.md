# UI localization

`platform/i18n.js` is a local classic script with no runtime dependency or
network request. The UI language is independent of typing language, selected
input layout and physical geometry. Russian is the default; English covers
legacy controls, diagnostics, map, progress, settings, errors and messages.

## API

- `TT2.i18n.t(key, params)` returns a dictionary message with `{name}` parameters.
- `TT2.i18n.setLanguage('ru' | 'en')` changes presentation and document `lang`.
- `TT2.i18n.init(document)` installs DOM translation for the legacy application.
- `TT2.i18n.translateText(text)` localizes a legacy generated UI message.
- `TT2.i18n.translateReport(text)` localizes an explicitly generated text report.
- `TT2.i18n.register(locale, dictionary)` adds a future locale without changing
  application components. New UI should use semantic keys.
- `TT2.i18n.keys` lists current dictionary keys; `.language` reads the selection.

New controls use `data-i18n="map.title"`, `data-i18n-title`,
`data-i18n-placeholder` or `data-i18n-aria-label`. A `data-i18n` element must
contain a plain label, not interactive child controls: its text is replaced.
For composed content, translate each label separately or use `t` while rendering.

The legacy bridge translates exact static messages and structured dynamic
fragments at the presentation boundary. A MutationObserver handles new results,
statistics and errors. WeakMap records retain each node's original source so
switching back to Russian restores it. Existing elements, values and event
listeners are preserved. New application logic should prefer semantic keys to
extendable legacy phrase mappings.

## Data boundaries

Exercise spans, virtual keyboard labels, actual character cells, custom text
and report textarea content are not translated by the DOM bridge. Attributes
such as textarea placeholders are translated without changing values. Use
`data-i18n-ignore` for additional user-owned content. The explicit report
translator must be called before clipboard output; DOM localization never
rewrites backups, storage records, typing materials or Unicode characters.

The localization module does not persist language settings: the platform store
owns that preference. It emits `tt:ui-language` after switching, allowing new
components to rerender language-specific labels. No system keyboard switching
or keyboard layout detection is performed here.

## Verification

`node tests/i18n.test.js` checks dictionary lookup, interpolation, structured
messages, reversible DOM updates, dynamic errors, unchanged exercise/user text,
placeholder/ARIA translations and preserved click handlers. As with the other
browser tests, Playwright is a test-only prerequisite. Chromium automation is
not proof of hardware behavior in Zen/macOS.
